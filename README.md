# مسار العينات

### منظومة توصيل العينات والمطابقة المالية الذكية

نظام ويب عربي كامل (RTL) لإدارة رحلة عينات المختبرات الطبية، من لحظة إنشاء المركز الطبي لطلب السحب وحتى إرجاع نتيجة التحليل، مع توثيق زمني دقيق، إشعارات فورية، سندات مالية، مطابقة ذكية مع تقارير المختبر، وحساب تارجت عادل وعمولات تصاعدية.

الواجهة مصممة باتجاه **clinically-luxury**: أخضر داكن `#0B6E63`، ذهبي `#C8A45D`، خلفية عاجية، أسطح زجاجية، وعناصر بصرية تعرض مسار العمل كخط أنابيب وتimeline واضح.

## 1. نظرة عامة

المشروع يحل مشكلة تتبّع العينات بين **المراكز الطبية** و**المختبر المركزي** في بيئة متعددة القطاعات والمراسلين. بدل الاعتماد على المكالمات والدفاتر، يوفّر النظام:

- مصدر واحد للحقيقة لكل طلب عينة.
- توثيق آلي لكل تغيير حالة على مستوى الخادم.
- رؤية مختلفة لكل دور بحسب صلاحيته.
- ربط مباشر بين حركة العينات والسندات المالية وتقارير المختبر.

الشاشة الافتراضية عند الدخول هي **«مركز العمليات»**، وهي لوحة موحّدة تجمع الطلبات والمهمات والتنبيهات ومؤشرات الأداء. بوابات الإدارة والمشرفين القديمة ما زالت متاحة من قائمة التنقل.

## 2. المميزات

### إدارة الطلبات
- إنشاء طلب عينة من المركز أو الإدارة أو المشرف، بنوع **عادي** أو **عاجل**.
- قائمة عمل مرتّبة **بالعاجل أولاً** مع بحث وتصفية حسب النوع والحالة.
- مؤشرات حيّة: الطلبات المفتوحة، العاجلة بانتظار الاستلام، بالمختبر، والمتأخرة عن SLA.
- خط أنابيب بصري يعرض توزّع الطلبات على المراحل الأربع.
- درج تفاصيل لكل طلب يعرض التواريخ الأربعة، الفواصل الزمنية، وسجل التدقيق الكامل.

### التنفيذ الميداني
- زر واحد لكل مرحلة، فيتولّى النظام التسجيل والإشعار.
- لوحة «إرشاد الميدان» تشرح الزر المناسب لكل مرحلة للمراسل.
- إسناد المراكز للمراسلين مع إعادة إسناد شاملة للطلبات المفتوحة.

### المالية
- سندات نقدي وآجل وضمان مع موافقات معلّقة.
- استخراج بيانات السند الورقي بالذكاء الاصطناعي عبر Gemini Vision.
- استيراد تقارير المختبر ومطابقتها آلياً مع السندات وحركة العينات.
- توزيع الفجوات المالية على المراسلين مع تتبّع حالة التسوية.
- تارجت مالي عادل، مؤشر جهد من 100 نقطة، وعمولات نقدية تصاعدية.

### الأدوات المساندة
- خريطة حيّة للمسارات مع إسقاط تخطيطي احتياطي عند غياب مفتاح Google Maps أو تجاوز الحصة.
- مسح QR/Barcode بالكاميرا أو إدخال يدوي أو اختيار سريع للدفعة.
- تقارير PDF رسمية جاهزة للطباعة بتخطيط A4، تشمل العمولات والمطابقة وحركة الطلبات والالتزام بالـ SLA.
- تصدير الطلبات إلى Excel مع التواريخ الأربعة والفواصل الزمنية، وتصدير التقرير النشط إلى Excel من نافذة التقرير.
- مركز تنبيهات بجرس وعدّ للمقروء وغير المقروء.

## 3. الأدوار والصلاحيات

| الدور | النطاق | ما يستطيع فعله |
|---|---|---|
| **الإدارة** `admin` | كل القطاعات | نظرة شاملة، تقارير، مطابقة مالية، عمولات، إسناد المراكز، تعديل الحالات، الإلغاء وإعادة الإسناد. |
| **مندوب القطاع** `supervisor` | قطاعه فقط | مراقبة طلبات القطاع، تصحيح النقرات الخاطئة، إعادة الإسناد داخل القطاع، تقارير المنطقة. |
| **المراسل الميداني** `courier` | المراكز المسندة إليه | عرض مهماته فقط، وتنفيذ مراحل الاستلام والتسليم والإرجاع بزر واحد لكل مرحلة. |
| **المركز الطبي** `center` | مركزه فقط | إنشاء الطلبات (عادي/عاجل)، متابعة الحالة لحظة بلحظة، وإلغاء الطلب قبل الاستلام. |

يتم التبديل بين الأدوار من الشريط الجانبي، وكل دور يرى بياناته فقط. تبديل الأدوار هنا أداة عرض تجريبية وليس تسجيل دخول؛ عند ربط المشروع بنظام مصادقة فعلي يجب استبدال اختيار الدور بالهوية المصادّقة عليها ومنع تمرير الدور من الواجهة إلى الخادم.

## 4. دورة حياة الطلب

الرحلة الأساسية تُعرف بـ **«الـ 3 نقرات»** لأن المراسل يتدخّل ثلاث مرات بعد إنشاء الطلب:

```
المركز ينشئ الطلب
        │
        ▼
   requested  ──(تأكيد الاستلام)──▶  picked_up
        │                                │
        │                        (تسليم للمختبر)
        │                                ▼
        │                        delivered_to_lab
        │                                │
        │                         (استلام العينات)
        │                                ▼
        │                        returned_to_center
        ▼
     cancelled (في حالات محددة)
```

كل انتقال يسجّل **أربعة طوابع زمنية من الخادم** وليس من جهاز المستخدم:

| الحالة | الحقل |
|---|---|
| طلب | `requestedAt` |
| استلام | `pickedUpAt` |
| تسليم للمختبر | `deliveredToLabAt` |
| إرجاع النتيجة | `returnedAt` |

ويُضاف لكل انتقال سجل في `auditTrail` يوضّح `action` و`byRole` و`byName` والوقت. كما يرفض الخادم أي تحديث قديم أو مكرّر برمز **409** لمنع التلاعب.

## 5. الإشعارات والتنبيهات

- **الطلب العاجل:** إشعار داخل النظام + رسالة SMS فوراً للمراسل.
- **الطلب العادي:** إشعار فوري، ورسالة SMS بعد حوالي دقيقتين إذا لم يتم الاستلام.
- تظهر التنبيهات في مركز التنبيهات مع قناة (`app` أو `sms`) والدور المستلم وحالة القراءة.
- يمكن تحديد تنبيه واحد أو الكل كمقروء.
- حالة الإرسال محفوظة في `notificationStatus` لكل طلب: `smsStatus` و`appSentAt` و`smsSentAt` و`escalationSentAt`.

> بوابة مزوّد SMS الحقيقي (مثل Twilio) تُستبدل من دالة واحدة في `server.ts` هي `sendSmsForMovement()`. في هذه النسخة تُخزّن الرسالة كتنبيه SMS داخل النظام.

### إنذار SLA

| نوع الطلب | الحد | تنبيه «قارب المهلة» |
|---|---|---|
| عادي | 90 دقيقة | عند 75% من المهلة |
| عاجل | 30 دقيقة | عند 75% من المهلة |

يظهر الطلب المتأخر بلون تحذيري في القائمة، ويُحتسب في مؤشر «متأخرة عن SLA».

## 6. الحالات الاستثنائية

| الحالة | السلوك |
|---|---|
| **إلغاء الطلب** | المركز يلغي قبل الاستلام. بعد الاستلام يحتاج موافقة المشرف أو الإدارة، ويُسجّل `cancelReason` و`cancelledAt`. |
| **تصحيح نقرة خاطئة** | المشرف أو الإدارة يعدّل الحالة، ويُسجّل إجراء `corrected` مع النص التوضيحي دون حذف السجل القديم. |
| **إعادة إسناد مركز** | كل الطلبات ما زالت بحالة `requested` تنتقل للمراسل الجديد، وتُضاف إدخالات `reassigned`، وتُعاد تهيئة الإشعارات. |
| **تحديث قديم أو مكرّر** | الخادم يرفضه برمز 409. |
| **طلب عاجل** | يتصدر قائمة العمل ويحصل على إشعار ورسالة فوريتين. |

## 7. السندات والمطابقة المالية

### أنواع السندات
- **نقدي `cash`** — يُحتسب في العمولة التصاعدية.
- **آجل `deferred`** — يُحتسب بنسبة عمولة ثابتة.
- **ضمان `guarantee`** — يبقى معلّقاً لحين قرار الإدارة أو المشرف.

حالات الاعتماد: `auto_approved`، `pending_review`، `approved_as_deferred`، `suspended`، `rejected`.

### المطابقة الذكية
- استيراد صفوف تقرير المختبر مع ربط الاسم بالمركز.
- مطابقة إجمالي المختبر مقابل السندات المعتمدة وحركة العينات لكل مركز.
- تصنيف النتيجة: `matched` أو `needs_review` أو `gap`.
- عند وجود فجوة يمكن إسنادها لمراسل أو تسويتها نقدياً أو تحويلها آجل أو استبعادها مع حفظ الملاحظة.
- دعم تداخل مراسلين متعددين على المركز الواحد مع عرض تفصيل مساهمات كل منهم.

## 8. التارجت والعمولات

### التارجت المالي العادل
يُحسب основе متوسط التحصيل التاريخي للقطاع، ومستوى القطاع (قوي/متوسط/نامٍ)، ونسبة النمو المستهدفة، مع إمكانية تعديل تارجت كل مراسل يدوياً.

### مؤشر الجهد (من 100 نقطة)

| المكوّن | الوزن |
|---|---|
| الانضباط في التوثيق والسندات | 40 |
| التغطية وسرعة دورة العينة | 35 |
| تحصيل المتأخرات وتنشيط المراكز الضعيفة | 25 |

### العمولات

| شريحة التحصيل النقدي | النسبة |
|---|---|
| حتى 1,000,000 ر.ي | 0.5% |
| من 1,000,001 إلى 2,000,000 ر.ي | 1% |
| فوق 2,000,000 ر.ي | 1.5% |

- السند الآجل يُحتسب بنسبة **0.5%**.
- الدرجة النهائية المرجّحة: **50% تحصيل مالي + 50% مؤشر الجهد**.
- مكافأة الشريحة الأعلى (1.5%) تُفتح فقط عند **جهد 70/100** أو أكثر، وتُستبعد من العمولة عند عدم الأهلية.

لوحة «ملخص التارجت والعمولات» تعرض شرائح العمولة والدرجة لكل مراسل، مع درج تفاصيل يسمح بتعديل التارجت.

## 9. الخريطة ومسح الباركود

- **الخريطة الحية:** تعرض المختبر المركزي والمراكز والمراسلين ومسارات الإرسال، وتعتمد على Google Maps. عند غياب المفتاح أو تجاوز حصة العرض التجريبي يظهر رسم تخطيطي تفاعلي بديل بالإحداثيات.
- **مسح الباركود:** يدعم صورة الكاميرا، والإدخال اليدوي، واختيار دفعة جاهزة. يقبل كود الدفعة الخام مثل `SMP-401` أو حمولة QR بصيغة JSON، وينقلك إلى طلب الدفعة لتحديث حالته.

## 10. التقارير والتصدير

- **تقرير PDF رسمي:** ثلاثة أوضاع داخل نافذة واحدة:
  - **كشف العمولات والتارجت:** ملخص نقد/آجل/عمولات، جدول المراسلين، معادلة الشرائح المصححة، وسطر إجمالي في نهاية الجدول.
  - **تقرير المطابقة الذكية:** إجماليات المختبر والسندات والفجوات، تفاصيل المراكز والضمانات والتداخل بين المراسلين، وسطر إجمالي.
  - **تقرير طلبات العينات والـ SLA:** الطوابع الزمنية الأربعة، الفواصل بالدقائق، حالة الالتزام لكل طلب، متوسطات الاستلام/المختبر/الإرجاع، وصفوف فارغة واضحة عند غياب البيانات.
- **جاهزية الطباعة:** ترويسة واضحة، عناوين أعمدة تتكرر في كل صفحة، منع تقسيم الصفوف والملخصات، وتخطيط أفقي A4 لتقرير الطلبات مع بقاء التخطيط الرأسي لتقارير المالية وملصقات الباركود.
- **تصدير Excel:** يصدّر الطلبات الظاهرة حسب الفلاتر الحالية، ويشمل رقم الدفعة، المركز، المراسل، النوع، الحالة، والتواريخ الأربعة مع الفواصل الزمنية بالدقائق. من نافذة التقرير يمكن تصدير التقرير النشط مباشرة إلى Excel (جدولي العمولات والمطابقة، أو جدول أوقات الطلبات). اسم الملف يتضمن الفترة الحالية.

## 14. المتغيرات البيئية

أنشئ ملف `.env` في جذر المشروع عند الحاجة (الملف مستبعد من Git):

```env
GEMINI_API_KEY=your_gemini_api_key
GOOGLE_MAPS_API_KEY=your_google_maps_api_key
VITE_GOOGLE_MAPS_API_KEY=your_google_maps_api_key
NODE_ENV=development
DISABLE_HMR=false
```

| المتغير | الاستخدام |
|---|---|
| `GEMINI_API_KEY` | استخراج بيانات السند الورقي. بدونة تُعطي نقطة OCR رسالة توضيحية. |
| `GOOGLE_MAPS_API_KEY` / `VITE_GOOGLE_MAPS_API_KEY` | عرض الخريطة. بدونة يعمل الإسقاط التخطيطي البديل. |
| `NODE_ENV` | يضبط سلوك الخادم في الإنتاج. |
| `DISABLE_HMR` | يوقف إعادة التحميل الساخن ومراقبة الملفات أثناء التحرير الآلي. |

لا ترفع ملف `.env` أو أي مفتاح API إلى GitHub.

## 15. واجهة الـ API

| الطريقة | المسار | الوصف |
|---|---|---|
| `GET` | `/api/config` | مفتاح الخرائط والتهيئة الخاصة بالعميل |
| `GET` | `/api/state` | حالة التطبيق الكاملة |
| `POST` | `/api/ai/scan-voucher` | استخراج بيانات سند ورقي عبر Gemini |
| `POST` | `/api/movements` | إنشاء طلب عينة جديد |
| `PATCH` | `/api/movements/:id/advance` | تقديم الطلب لمرحلة التالية مع فحص 409 |
| `POST` | `/api/movements/:id/cancel` | إلغاء الطلب |
| `POST` | `/api/movements/:id/correct` | تصحيح حالة الطلب مع سجل تدقيق |
| `PATCH` | `/api/centers/:id/courier` | إعادة إسناد مركز لمراسل آخر |
| `POST` | `/api/movements/scan-qr` | تحديد دفعة عبر QR/Barcode |
| `POST` | `/api/vouchers` | إضافة سند |
| `PATCH` | `/api/vouchers/:id/decision` | قرار الإدارة على سند الضمان/المعلّق |
| `POST` | `/api/lab-import` | استيراد صفوف تقرير المختبر |
| `POST` | `/api/reconciliation/resolve` | تسوية أو إسناد فجوة مالية |
| `PATCH` | `/api/couriers/:id/target` | تعديل تارجت المراسل |
| `POST` | `/api/centers` | إضافة مركز طبي |
| `PATCH` | `/api/notifications/:id/read` | تحديد تنبيه كمقروء |
| `PATCH` | `/api/notifications/read-all` | تحديد كل التنبيهات كمقروءة |
| `POST` | `/api/reset-demo` | إعادة البيانات إلى نسخة البداية |

كل مسارات `/api` تُدار من `server.ts`. في وضع الإنتاج يقدّم الخادم ملفات الواجهة المبنية أيضاً.

## 16. نموذج البيانات

الحالة الكاملة في `AppState` تتكوّن من:

| الكيان | الوصف |
|---|---|
| `currentPeriod` | الفترة الحالية المعروضة |
| `labLocation` | إحداثيات المختبر المركزي |
| `sectors` | القطاعات والمشرفون ومستوى كل قطاع |
| `centers` | المراكز الطبية، العناوين، الإحداثيات، المراسل الأساسي، المتوسط الشهري والمتأخرات |
| `couriers` | المراسلون، مواقعهم، التارجت، ومعدّلات الأداء |
| `movements` | طلبات العينات وحالاتها وتواريخها وسجل التدقيق والإشعارات |
| `vouchers` | السندات بأنواعها وحالات اعتمادها |
| `labRows` | صفوف تقارير المختبر المستوردة |
| `gapAttributions` | إسناد الفجوات المالية وحالات تسويتها |
| `notifications` | تنبيهات النظام والرسائل النصية |

أنواع مساعدة مهمة: `MovementStatus`، `RequestType`، `MovementAuditEntry`، `MovementNotificationStatus`، `VoucherType`، `ReconciliationStatus`، `CourierEvaluation`، `CenterReconciliation`.

## 17. التخزين وبيانات البداية

- تُحفظ الحالة في `data/db.json`، ويقوم الخادم بإنشائها تلقائياً عند أول تشغيل.
- عند افتتاح قاعدة بيانات قديمة يضيف الخادم الحقول الجديدة (الإحداثيات، حقول سير العمل) دون حذف البيانات.
- بيانات البداية الحالية **شبه جديدة** ومحدودة:

| العنصر | العدد |
|---|---|
| القطاعات | 3 |
| المراكز | 6 |
| المراسلون | 3 |
| الطلبات | 1 (`SMP-401` بحالة `requested`) |
| السندات | 0 |
| صفوف المختبر | 0 |
| الفجوات | 0 |
| التنبيهات | 1 |

لإعادة ضبط البيانات إلى هذه الحالة في أي وقت:

```bash
curl -X POST http://localhost:3000/api/reset-demo
```

> بما أن `data/db.json` مستبعد من Git، فإن أي مستنسخ جديد للمستودع سيحصل على بيانات البداية تلقائياً عند أول تشغيل للمشروع.

## 19. ملاحظات قبل الرفع على GitHub

- لا توجد مستودع Git مهيّأ في المجلد حالياً؛ الرفع متروك لك بالكامل.
- `.gitignore` يستبعد `node_modules/`، و`dist/`، و`data/db.json`، وملفات `.env`، والسجلات، وملفات النظام.
- `requirements.txt` مرفق كمرجع للحزم لأن المشروع Node/TypeScript؛ المصدر المعتمد للتثبيت هو `package.json` و`package-lock.json` عبر `npm install`.
- تأكد من عدم وجود مفاتيح API داخل الكود أو ملفات البيانات قبل الرفع.
- بعد الاستنساخ: `npm install` ثم `npm run dev` — لا حاجة لنسخ `data/db.json`.
